# LTD Capability Mesh Operating Model

Chummer owns product truth, story truth, package truth, release truth, support truth, rules truth, and identity truth.

LTDs are bounded adapters for:

- capture
- draft
- projection
- notification
- review
- audit

Authority boundaries:

- Product signals stay first-party in Chummer and may mirror to a hosted board.
- Dispatches stay receipt-backed and may use external draft assistance, but drafts never publish directly.
- Projection tables are operator mirrors only and never feed runtime truth back into Chummer.
- Voice capture becomes a structured EA packet before any downstream repo action.

Current mesh:

- `ProductLift.dev`: public signal mirror only
- `Teable`: operator projection only and operations cockpit
- `Syllabbles`: dispatch draft only
- `blipai.app`: operator voice capture only
- `Emailit`: delivery adapter only
- `1min.AI`: bounded synthesis fallback
- `BrowserAct`: verification and account-fact capture
- `vexp.dev`: cross-repo opportunity index and lane discovery only
- `AI Magicx`: interactive overflow support drafts only (staged)
- `OMagic`: capacity discovery lane (staged, no production routing)

Required proof:

1. Chummer creates the first receipt.
2. The LTD adapter creates a projection or draft receipt.
3. Public copy never exposes provider names or secret-bearing internals.
4. Private support and campaign data never enter public or draft lanes.
5. Every staging lane is tied to a target output artifact and freshness check.

### July 2026 update

The operating model now treats the LTD stack as a governed execution fabric:

- `1min.AI` is the default low-risk background capacity lane for non-urgent draft and transform work.
- `vexp.dev` is the cross-repo opportunity finder; it must not be the final judge, only the discovery/scan authority.
- `Teable` is the live operations cockpit for LTD rows, stale proofs, and operator evidence.

No provider can be promoted into product-critical runtime truth from this mesh without:

- source packet alignment
- freshness gate pass
- capacity/route receipt
- proof-debt closure or explicit exception
- explicit operator approval trail
