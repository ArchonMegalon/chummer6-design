## Capability freshness and quota state

The private schema is `GOVERNED_SPATIAL_RENDER_CAPABILITY_QUOTA_EVIDENCE.schema.yaml`.
It requires exact `issued_at`, `expires_at`, artifact family/content profile, provider-route digest, environment, gate versions, evidence refs and hashes, revocation state, authorization, idempotency, quota state, kill-switch epoch/state, and signature.

The one allowed signature profile is Ed25519: `algorithm: ed25519`, `encoding: base64url_no_padding`, an 86-character canonical unpadded base64url `signature_value` representing exactly 64 bytes, non-empty opaque `key_ref`, non-negative `key_epoch`, `key_fingerprint` in `sha256:<64_lowercase_hex>` form, `canonicalization: rfc8785_jcs`, `signed_payload_scope: entire_receipt_excluding_signature_value_and_signed_payload_digest`, and a SHA-256 `signed_payload_digest`.
No `none`, provider-specific, generic-algorithm, alternate-signature, or unsigned fallback exists.

The canonical semantic verifier removes only `signature.signature_value` and `signature.signed_payload_digest`, RFC 8785 JCS canonicalizes the remaining JSON, SHA-256 hashes those canonical UTF-8 bytes, compares the digest, decodes exactly 64 signature bytes, resolves `key_ref`, `key_epoch`, and `key_fingerprint` to an active issuer-owned Ed25519 key for the exact environment and exact owner, checks `key.not_before <= issued_at <= expires_at <= key.not_after`, and verifies Ed25519 over the same canonical bytes.
Unknown, mismatched, revoked, not-yet-valid, or expired keys and every algorithm, encoding, scope, canonicalization, digest, epoch, or signature mismatch fail closed to `unverified_or_blocked`.
This is a design contract and in-memory design validation, not runtime key-registry or verifier implementation evidence.

The raw receipt profile is deliberately bounded to valid UTF-8 JSON containing objects, arrays, valid Unicode strings, signed safe integers, booleans, and null. Duplicate names, BOMs, malformed UTF-8, unpaired surrogates, every float token including decimal/exponent/negative-zero forms, non-finite values, and integers outside `-9007199254740991..9007199254740991` fail before schema validation or signing. Within that no-float domain, canonical object keys use UTF-16 code-unit order and compact Unicode-preserving JSON scalar serialization; locale collation and Python code-point `sort_keys` are not accepted as JCS evidence.
