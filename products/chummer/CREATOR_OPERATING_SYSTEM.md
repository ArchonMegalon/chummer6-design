# Creator Operating System

## Purpose

This file defines how creator publication becomes a live operating system instead of a static artifact shelf.

## Product rule

Creators should not only be able to publish.
They should be able to learn whether their work is compatible, adopted, healthy, and worth updating.

## Required surfaces

The first creator operating system should include:

* publication dashboard
* compatibility and breakage posture
* adoption-band visibility
* moderation and trust status
* update request and support issue visibility
* collateral and promo readiness

## Why this matters

If creators cannot see whether anyone can safely use their work, publication becomes a graveyard instead of an ecosystem.

## Boundary rule

The creator operating system must stay bounded by privacy and compatibility policy.
It should not expose private campaign or player internals.
