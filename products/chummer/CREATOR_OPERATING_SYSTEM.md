# Creator Operating System

## Purpose

This file defines how creator publication becomes a live operating system instead of a static artifact shelf.

## Product rule

Creators should not only be able to publish.
They should be able to learn whether their work is compatible, adopted, healthy, and worth updating.
Trust ranking should stay discoverability language, not endorsement language.

## Required surfaces

The first creator operating system should include:

* publication dashboard
* compatibility and breakage posture from receipt-backed registry truth
* adoption-band visibility
* moderation status with appeal or restoration posture
* trust-ranking posture with visible reason chips instead of hidden score math
* update request and support issue visibility
* collateral and promo readiness

## Claim boundaries

Compatibility posture, moderation status, and trust-ranking posture must stay distinct.
The surface may not imply that a moderated artifact is compatible, that a compatible artifact is endorsed, or that a high-ranked artifact is safe for every table.

## Why this matters

If creators cannot see whether anyone can safely use their work, publication becomes a graveyard instead of an ecosystem.

## Boundary rule

The creator operating system must stay bounded by privacy and compatibility policy.
It should not expose private campaign or player internals.
It should follow `CREATOR_PUBLICATION_TRUST_AND_COMPATIBILITY_POLICY.md` whenever a shelf, dashboard, or signed-in surface summarizes trust, moderation, compatibility, or adoption.
It should follow `ARTIFACT_SHELF_POLICY.md` whenever creator-owned shelves surface locale, retention, inspectable source truth, or public-versus-creator audience boundaries.
